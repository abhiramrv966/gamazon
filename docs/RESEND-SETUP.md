# Resend email setup

Resend is the selected email provider. Supabase Auth generates and verifies sign-in codes, and delivers them through Resend SMTP. The app continues using its existing Supabase Auth calls; it does not need a Resend SDK or a public email-sending endpoint.

Status: prepared, not activated. The sender domain and credentials are pending. No email has been sent as part of this setup.

## 1. Verify the sender domain

After buying the domain, add a sending subdomain such as `auth.example.com` in Resend → Domains. Replace `example.com` with your domain. Copy the DNS records generated by Resend to your DNS provider, and wait for verification. Use a sender on that verified subdomain, such as `login@auth.example.com`.

Follow [Resend's domain verification guide](https://resend.com/docs/add-a-domain). DNS record values must come from your Resend account; the example domain above is not a configured sender.

## 2. Create the SMTP credential

In Resend → API Keys, create a key named `Gamazon Supabase Auth`. Select Sending access and restrict it to the verified sending domain. The API key is the SMTP password. Store it in Supabase's SMTP settings, not in Git or a `NEXT_PUBLIC_` variable. The Next.js runtime does not need this key.

See [Resend's API key guide](https://resend.com/docs/create-an-api-key).

## 3. Configure Supabase

Open your Supabase project → Authentication → Email (under Notifications) → SMTP Settings. Enable custom SMTP and enter:

| Setting      | Value                                     |
| ------------ | ----------------------------------------- |
| Host         | `smtp.resend.com`                         |
| Port         | `465` (TLS)                               |
| Username     | `resend`                                  |
| Password     | Your Resend API key                       |
| Sender name  | `Gamazon`                                 |
| Sender email | An address on the verified sending domain |

Source: [Resend's Supabase SMTP guide](https://resend.com/docs/send-with-supabase-smtp).

## 4. Use code emails

In Supabase's email templates, use the HTML in `docs/email/auth-code.html` for Magic Link. Use the same code-based body for Confirm signup if it is used for new identities. Suggested subjects are `Your Gamazon sign-in code` and `Verify your email for Gamazon` respectively.

Keep `{{ .Token }}` unchanged. The app accepts an emailed code, so these templates do not need a confirmation-link button. This does not grant community membership or administrator access; the existing invitation and owner-bootstrap rules still apply.

Review OTP expiry and authentication rate limits before opening membership. Follow [Supabase's email OTP guide](https://supabase.com/docs/guides/auth/auth-email-passwordless).
